## Honest Feedback

1. **The `printf` format-string-recycling bug was a real, avoidable correctness mistake** in
   code I wrote and initially trusted on thin evidence. `printf -v var 'fmt %q' "$@"` is a
   known footgun (format strings repeat when there are more args than specifiers) — I should
   have known this going in, not discovered it via a side-by-side output comparison after the
   fact. Lucky that the discrepancy was checkable (JSON output diff) rather than a silent data
   corruption in a fire-and-forget `maw hey` call.

2. **`maw doctor`'s remediation hints were sometimes generic, not literal commands** — its
   suggestion for the plugins issue was `maw plugin install`, but that subcommand actually
   requires a source dir/URL argument and errors without one. Had to explore the filesystem
   myself to find a real plugin candidate rather than following the hint verbatim. Minor
   friction, easily worked around, but worth knowing `doctor`'s hints aren't always
   copy-pasteable.

3. **Re-reading `maw plugin ls -v` after a successful install still printed "no plugins
   installed" / exit 1**, contradicting `maw doctor`'s "1 loaded" in the very next command.
   I noted the discrepancy and trusted `doctor` (which cross-checks against the actual
   filesystem state) over `ls -v`, but didn't chase down why `ls -v` disagreed — plausibly a
   real bug in `maw-rs` itself, not something introduced by the wrapper, but unconfirmed.

## Lessons Learned

- **`printf -v var 'FMT %q' "$@"` recycles the format string once per extra positional
  argument** — if `FMT` contains a literal prefix (like `maw `) you want exactly once, it will
  be duplicated for every argument beyond the first. Build a fixed prefix separately from the
  per-argument `%q` expansion (e.g. `printf -v args '%q ' "$@"; cmd="prefix $args"`), never
  bake the prefix into the recycled format string.
- **Before declaring a shell wrapper/proxy script "working," test it with the actual argument
  shape it's meant to carry** — flags plus positional args together, and (if it will ever
  carry human-composed text) a multi-line string with special characters — not just the
  simplest single-arg smoke test. A wrapper that "works" on `--version` can still corrupt a
  two-argument call.
- **When a tool's own health-check suggests a remediation command, verify the command's
  actual signature before assuming it's copy-pasteable** — `doctor`/linter-style hints are
  often abbreviated and may need an argument the hint text omits.
- **When two commands from the same tool disagree about state (e.g. `doctor` says "1 loaded",
  `ls -v` says "none"), prefer whichever cross-checks against real state** (filesystem,
  running process) over the one reporting through its own internal bookkeeping — but flag the
  discrepancy rather than silently picking one, in case it's a genuine tool bug worth reporting
  upstream.
